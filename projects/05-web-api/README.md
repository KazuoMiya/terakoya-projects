## 準備（venv の中で）

```bash
cd projects/05-web-api

pip install -r requirements.txt   # FastAPI・uvicorn・テスト道具が入る
```

雛形には `/health` だけ実装してある。まず動かして「一周」を見よう。

```bash

```

FastAPI は「型を書くと、検証と説明書がついてくる」道具だ。止めるのは Ctrl+C。

## 作るもの（APIの仕様）

| メソッドとパス | 役割 | 認証 | 主な応答 |
|---|---|---|---|
| GET `/health` | 生存確認（実装済み） | 不要 | 200 |
| GET `/servers` | サーバー一覧 | 不要 | 200 |
| POST `/servers` | サーバー登録 | **必要** | 201 / 401 / 409 / 422 |
| GET `/servers/{id}` | 1件取得 | 不要 | 200 / 404 |
| POST `/servers/{id}/checks` | 点検結果の記録 | **必要** | 201 / 401 / 404 / 422 |
| GET `/servers/{id}/checks?limit=N` | 点検結果の一覧（**新しい順**） | 不要 | 200 / 404 |

### 入力の形と検証

- **Server**: `hostname`（1〜64文字・必須・**重複は409**）、`role`（1〜32文字・必須）
- **Check**: `metric`（1〜64文字）、`value`（数値）、`status`（**課題1から使ってきた4値だけ**:
  OK / WARNING / CRITICAL / UNKNOWN。それ以外は422）

検証は Pydantic のモデルで書く。型と制約を書けば、422 は FastAPI が自動で返す——
**全ての書き込みに文字列長の制限を**、を自分で if 文の山にしなくていい。

### ステータスコードの使い分け（この課題の学びどころ）

| コード | 意味 | この課題での例 |
|---|---|---|
| 401 | 誰か分からない | X-API-Key が無い・違う |
| 404 | 対象がいない | 存在しない server_id |
| 409 | 状態が衝突 | hostname の重複（入力の形は正しいが、いまの状態と衝突） |
| 422 | 入力の形が不正 | hostname が空・status が4値以外・value が数値でない |

### 認証 — APIキー1個まで

書き込み系（POST）は、リクエストヘッダ **`X-API-Key`** が `.env` の `API_KEY` と
一致したときだけ通す。読み取り系（GET）は認証なしでよい。
OAuth やセッション管理には踏み込まない——**この課題の認証はここまで**と決めてある。

### エラーメッセージも設計のうち

エラーで返してよいのは「使う人が直せる情報」だけ。テーブル名・SQL・Traceback のような
内部情報をクライアントに返さない（採点にも入っている）。

## 設計の約束 — SQLは db.py だけに書く

`src/db.py` がDBアクセス層だ。**app.py にSQLを1行も書かない。**
この分離は、最後の挑戦「SQLite → PostgreSQL 差し替え」のためにある。
SQLが散らばっていれば全ファイル改修、閉じてあれば1ファイル差し替えで済む。
`init_db()`（テーブル定義）は仕様で決まっているので実装済み。残りの6関数を書く。

## 挑戦（任意）: SQLite → PostgreSQL 差し替え

課題2の PostgreSQL（docker compose）がまだ手元にある。db.py を psycopg 版に
差し替えてみると、**3つの穴**に順番に落ちる——それが学びだ。

1. **プレースホルダが違う**: sqlite3 は `?`、psycopg は `%s`。
   SQLを db.py に閉じ込めたのは、この差し替えを1ファイルで済ませるためだった。
2. **`lastrowid` が使えない**: PostgreSQL では `INSERT ... RETURNING id` に書き換える。
3. **コミットの流儀が違う**: sqlite3 の `with conn:` は commit するが接続は閉じない。
   psycopg の `with connect() as conn:` は commit して**接続も閉じる**。
   エラー後に同じトランザクションでクエリを続けると `InFailedSqlTransaction` になる
   （rollback してから続ける）。

うまく動いたら、あなたのAPIは「開発はSQLite、本番はPostgreSQL」を知る道具になった。
