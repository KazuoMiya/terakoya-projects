# 手順書 — リリースとロールバック（穴埋めテンプレート）

守る②で、この手順書を**自分の環境の実際のコマンドで**埋める。
手順書は「読んでから動く」ためのもの（開発の現場・リリース当日の回）。
埋めたら、**手順書だけを見て**もう一周できるかを試すこと——それが手順書のテストだ。

> **鉄則: ロールバック手順を先に書く。戻せないリリースはリリースではない。**

- 事前条件: <例: main が緑（PRの自動採点が通っている）こと>

## 1. リリース手順

| # | やること | コマンド | 確認 |
|---|---|---|---|
| 1 | 直前のバックアップ | `<例: bash deploy/backup.sh ... >` | バックアップ完了の表示 |
| 2 | 新しいコードを取る | `<git pull など>` | 取れたコミットIDを控える |

## 2. ロールバック手順（先に書く）

「リリース後、/health が返らない・エラーが増えた」と判断したら、迷わずこちら。

| # | やること | コマンド | 確認 |
|---|---|---|---|
| 1 | 直前のコミットへ戻す | `<git switch --detach <控えたID> など>` | |
| 2 | 再起動 | `<sudo systemctl restart terakoya-api>` | active (running) |
| 3 | 動作確認 | `<curl http://localhost/health>` | `{"status":"ok"}` |
| 4 | 報告 | 戻したこと・気づいたことを記録する | |
